# 每日任务（1.7.3）

## 显示与交互

正常游戏：屏幕左侧常驻紧凑 HUD，无大底板；一次显示全部每日任务与主线任务，并显示标题、详情、进度、奖励、领取和刷新操作。每日任务与主线任务标题右侧分别有对齐的「显示/隐藏」开关，折叠状态保存在客户端配置中，重启后仍保持。

打开聊天或背包后 HUD 不消失，此时可用鼠标悬浮任务查看完整详情、悬浮原生奖励图标查看说明，也可直接点击「领取」或「刷新」。刷新仍保留二次确认，并继续受每天共享一次免费更换限制。经验等级奖励直接绘制原版经验球纹理，数量显示在图标右侧；悬浮时明确显示实际是经验等级奖励，并不会发放经验瓶物品。已完成任务使用勾选、亮色边条和背景强调，领取后仍保留明确的完成状态。
F1 隐藏 GUI、F3 调试界面和其他界面打开时不重复绘制 HUD。

**F8** 打开任务界面，解除鼠标锁定，悬浮奖励查看与背包一致的物品提示，点击「领取」发奖。
这是非暂停界面，打开后世界仍会运行。按 F8 或 Esc 关闭，按键可在游戏「选项 → 控制 → 按键绑定 → muxi」修改。
任务按钮支持键盘焦点；任务超过窗口容量时可以滚动。
F8 界面显示「免费更换 1/1」及每项的「换一项」。更换前有二次确认，提示清空该任务进度；已完成或已领取的任务不能更换。
生存背包左侧至少剩余 120 GUI 像素时也显示交互侧栏；打开配方书时先扣除配方书占位，空间不足时让位给背包，仍可用 F8。
侧栏不是物品槽，不会让光标中拿着的物品因点击「外部区域」而掉落。

图标不是静态图片：奖励通过原生 `ItemStack.STREAM_CODEC` 传输，以原生物品模型、叠加数量、附魔光效和耐久显示，
提示框使用物品堆本身。模组物品也可作为奖励，前提是双方都安装了该物品所属模组。

客户端本地设置：`config/muxi-daily-tasks-client.json`（第一次更改侧栏显隐时保存）：

```json
{"visible":true,"left":12,"width":190,"topFraction":0.3}
```

## 每日分配与进度

F8 界面顶部同时提供“每日任务”和“主线任务”页签。首版主线页只显示一个静态任务：**请联系服务器管理员联系夏意**；它不参与每日任务的随机、进度、奖励、换项或玩家存档。

服务端第一次启动自动创建 `config/muxi-daily-tasks.json`，默认启用，每日北京时间 00:00 刷新。
`timezone`、`resetHour`、`dailyCount`、`hardCount` 均可调整；普通加困难合计最多 5 个，困难最多 1 个。
默认 3 个普通 + 第四个困难，任务池 27 项：17 个普通（含食品制作、收获、采花和射击）、10 组传奇狩猎。
普通任务优先覆盖不同 group（采矿/战斗/生活），困难从独立池抽取，始终放在最后。每位玩家独立；同一 UUID 同一天不会因重新登录重抽。
任务**类型**会从可用模板中随机抽取；普通槽仍受 group 多样性、跨天去重和已安装模组约束，因此不是所有模板完全等概率。
任务**要求数量与奖励数量**也会在各模板声明的范围/离散档位内随机生成。所有随机只发生在初次分配或免费更换时，随后保存为具体快照；同一天重登、反复打开 HUD、领奖都不会重新随机。
跨天选择避开上一任务日出现过的全部任务 ID，包括被换掉的任务；默认池容量足够时不重复。自定义池过小才允许回退重复以填满任务栏。
这里保存的是「上一次实际分配的任务日」：离线几天后也避开上次登录的任务，不虚构离线期间的分配历史。
每天所有任务共享一次免费更换，不是每项一次。优先换同组、同难度且昨天没出现过的任务；困难只能换困难，不增加困难槽位。
候选池为空时不消耗次数；新任务按更换时的统计建立新基线、从 0 开始。原任务及原进度被替换，无奖励。完成后不能靠更换再拿第二份奖励。
只统计本轮任务分配以后的增量，不把以前的累计成就当作今日进度。未领取奖励随每日刷新到期，不跨日保留。
服务器时钟回拨到旧日期不会重新发放更早日期的任务。

支持的计数方式：

| kind | targets 的含义 |
| --- | --- |
| mined | 方块 ID，对应服务器「挖掘次数」统计 |
| crafted | 物品 ID，对应服务器「制作数量」统计 |
| killed | 实体 ID，对应服务器「击杀次数」统计 |
| custom | 原版/已注册自定义统计 ID，如 `minecraft:fish_caught` |
| gun_hit | 对敌对目标的 TaCZ 有效弹丸命中；空 targets 表示任意敌对生物 |
| gun_headshot | TaCZ 服务端确认、并且造成实际伤害的爆头 |
| gun_kill | TaCZ 弹丸击杀，需在 tick 末端核实真正死亡 |
| champion_killed | 指定实体 ID 的 Champions 击杀，另有 minTier 阶级要求 |
| defeated | 本人及有明确主人的辅助击杀，由死亡事件计数，不叠加原版击杀统计 |
| harvested | 成熟作物收割株数，空 targets 为任意受支持作物；支持破坏和 RightClickHarvest 右键收割 |
| flowers | 采花产生的花朵数量，空 targets 为任意标准花朵或额外任务花朵标签 |

多个 targets 累加，`divisor` 将原始单位转为显示单位。五千步任务将步行/疾跑厘米之和除以 100：行进一格折算一游戏步，共 5000 格，约 5 公里；不是现实步幅或脚步动画计数，不计传送和飞行。
每秒一次进度检查，仅对在线玩家的少量统计条目做查表，不扫描世界，不增加实体遍历。
统计会在下一次服务端检查时同步；极端卡顿时这不是严格一秒墙钟延迟。

**统计类计数边界**：采矿、食品制作、钓鱼和步行仍要求相应服务器统计增加；机器自动制作是否计入，取决于机器是否记录玩家制作统计。
普通击杀已改用 `defeated`，本人、女仆、傀儡装配和 OwnableEntity 宠物都按真实主人归属；只给有归属的在线主人计数。
不按距离猜主人，不共享给其他玩家，不直接读写离线玩家档案。没有主人 UUID 的原版铁傀儡不自动归给最近玩家。
作物按「成熟收割一株计一次」，不是随机产物/种子的总掉落数。识别 CropBlock、标准作物标签及 `muxi_game_core:task_crops`；有 age 属性的非 CropBlock 作物须达最大 age。
花朵识别 `minecraft:flowers` 和 `muxi_game_core:task_flowers` 方块标签；必须实际采下并产生花朵掉落，背包变化或扔出重捡不算。模组不遵循标准标签/成熟度接口时，可通过数据包补充任务标签或另做适配。
收获/采花没有自然来源追踪，玩家种下后收割合法；本版不承诺禁止反复放置花朵再采集。
挖掘统计本身不区分矿石是否曾被玩家放置，本版没有增加矿石来源追踪，也不承诺完全防刷。
射击要求实际生命伤害记录与 TaCZ Post/Kill 事件相互印证；同一射手/弹丸/目标只计一次。霰弹不同弹丸、穿透的不同目标可分别计数，不是扣一次扳机就加一次。
普通/传奇狩猎和枪械清剿支持自己辅助单位的击杀。练枪命中与爆头仍要求本人操作，不由辅助代练。
玩家、宠物和被驯服单位不能作为刷任务的敌对目标；普通/精英怪不能冒充传奇，死亡被取消或目标恢复存活时不算击杀。
Champions 的本地版本中 4 阶=传奇、5 阶=终极。默认 minTier=4，因此更高的 5 阶同种怪也算，错种怪不算。任务不提高稀有怪刷新率、不额外生成目标。

困难覆盖僵尸、骷髅、蜘蛛、苦力怕、末影人、幻翼、溺尸、女仆妖精（`touhou_little_maid:fairy`）八种敌人。

困难奖励附魔金苹果随机 1–2、绿宝石 8、等级 +1。普通奖励没有附魔金苹果，也不奖励面包或其他食品。
新增四种食品均为已安装农夫乐事 1.3.4 中的工作台复合配方，目标低数量、绿宝石奖励在 **4–8** 内逐整数随机，成品保留不收走。
矿物/材料奖励使用离散档位：**只会出现 `2 / 4 / 8 / 16 / 32`**。默认按稀有度加权：煤、铜、红石、青金石权重较高且倾向 8–32；铁居中；金较少且倾向 2–8；绿宝石、钻石最低权重且只给 2/4 这一档位。`矿洞寻铁` 有两个矿物奖励槽，所以可能形成“钻石 2 + 煤 32”或“铁 16 + 青金石 8”之类的组合；另外两项采矿任务默认只抽一个矿物槽，避免奖励膨胀。
奖励候选支持 `variants` 与每个候选的 `weight`；权重只影响出现概率，最终数量仍受各候选自己的离散档位限制。
箭与火把的一组是 64；所安装 TaCZ 默认 9mm 子弹的一组是 **60**（ammo index 的 stack_size），不能用非法 64 堆叠代替。不修改任何物品堆叠规则。

## 配置示例

```json
{
  "schema": 2,
  "enabled": true,
  "timezone": "Asia/Shanghai",
  "resetHour": 0,
  "dailyCount": 1,
  "hardCount": 0,
  "pool": [{
    "id": "coal_miner",
    "group": "mining",
    "title": "收集燃料",
    "description": "亲手挖掘 32 块煤矿石或深层煤矿石。",
    "kind": "mined",
    "targets": ["minecraft:coal_ore", "minecraft:deepslate_coal_ore"],
    "goal": 32,
    "divisor": 1,
    "unit": "",
    "rewards": [{"id":"minecraft:iron_ingot","count":8}],
    "experienceLevels": 1
  }]
}
```

每项至多 4 个物品奖励；每个物品堆数量不超过其合法堆叠上限和 64。
`rewards` 接受原生 ItemStack JSON，可以添加 `components`，如自定义名称、附魔、耐久、Lore。
TaCZ 子弹用 `{"id":"tacz:ammo","ammoId":"tacz:9mm","count":60}`；使用原生 AmmoItemBuilder 创建包含弹种组件的真实物品。此形式不能同时传 components。
`requiresMods` 可声明可选依赖；缺少 TaCZ 时不分配射击任务，缺少 Create 时跳过黄铜奖励任务，缺少 Champions 时没有传奇困难任务。原有任务快照不会因重载而静默改奖。
服务端启动/重载会用当前注册表校验物品和组件，未知 ID 不会被偷偷替换为空气。
默认任务池资源：`src/main/resources/muxi/daily-tasks-defaults.json`。已有服务端配置不会被新版本覆盖。

命令：`/muxi tasks` 查看，`/muxi tasks claim <id>` 领取，`/muxi tasks reroll <id>` 更换一项，管理员权限 2 的 `/muxi tasks reload` 重载配置。
配置重载不会替换玩家已经分配的目标和奖励快照，新的任务池在下次日更分配时使用。
1.5 的 schema 1 配置/存档可以读取，旧的正数 experience 字段只转换为 +1 级，绝不会变成 +10/+15 级。其旧目标和物品奖励保留；已有管理员配置不会被默认池覆盖。需要新任务池时先备份并更新公开任务配置，再等待日更，不删除玩家领取记录。
无效重载保留上一份有效配置；首次启动配置无效则只停用任务功能并记录错误，不更改登录核验配置。

## 奖励、存档与协议

服务端校验真实发包玩家、日期、任务 ID、进度、领取位；协议不接受客户端提交的 UUID、奖励、数量或进度。
查看/领取请求限频。背包装不下全部奖励时不部分发奖、不标为已领取、不把物品随意丢在地上。
只向主背包 36 格发奖，不偷偷移动副手、护甲、饰品或容器中的物品。

进度与领取位保存在玩家文件的 `NeoForgeData.PlayerPersisted.muxi_daily_tasks`，与背包、经验位于同一份 NBT，
领奖会立即调用原版单玩家保存；普通进度随玩家正常存档。死亡克隆、重登保留状态。
这不等于外部备份回滚、磁盘损坏、第三方存档模组异常情况下的全局交易系统；普通未保存进度也可能随崩溃回退。

建议两端一起更新到 1.7.x，沿用 v2 协议；不把字段布局不同的包发给 1.5 客户端。通道标为 optional，旧客户端退回文本指令。
独立的单人世界使用本地逻辑服务器做同样的校验，不读取服务器身份密钥。

集成测试的命中位置/爆头标记是测试输入，不等于端到端验证真实客户端瞄准、子弹飞行或整个整合包。模组自身的版本检查可能访问上游，本测试不使用账户密钥。

这些测试不代替整合包内的联网实测与其他 HUD/模组兼容性验收。
仅 `build/libs/muxi-game-core-1.7.0.jar` 是发行产物；测试专用 `muxi-tasks-smoke-only.jar` **禁止分发到实际整合包**。

## 随机模板与扩展测试

`goal` 是下限，`goalMax` 是可选上限，`goalStep` 控制离散步长；例如 `goal=24, goalMax=32, goalStep=4` 只会生成 24/28/32。任务描述里的 `{goal}` 在分配时替换。
奖励支持 `count`（下限）、`countMax`（上限）、`countStep`（步长，默认 1）。例如 4/8 绿宝石使用 count=4,countMax=8,countStep=4。
模板范围在初次分配或免费更换时确定，生成具体快照；快照不再带上限或随机规则。HUD 预览、实际发奖、重连和存档读写始终使用同一具体数值。
旧配置不会被默认池覆盖，已分配的旧任务仍保留原快照；本轮只更新源代码和产物，不直接替换正式服配置。

`python tests/run_tasks_smoke.py --extended` 在新建隔离服加载本机已安装的女仆、傀儡、农夫乐事、RightClickHarvest、TaCZ、Champions、Create 及依赖。
测试用真实模组实体/伤害/收割接口验证归属和 OR 条件；玩家与枪械报告为测试输入。另注册测试专用带标准标签和掉落表的花朵验证模组花通路；并非穷举整合包全部植物。

部署应在正常停服后备份并替换服务端的旧 Core，同时替换客户端包的 Core，避免目录中有多个版本。
