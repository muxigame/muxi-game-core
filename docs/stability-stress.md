## 环境与范围

- 本机回环地址，新建一次性世界；不启动生产服务器，不连接生产信令服务器。
- 家园和生存各两个原生 Minecraft 自动化客户端，位置相隔 2,048 格。
- 全整合包、维度 tick / 原生加载线程、前方区块预加载启用，C2ME 不参与。
- JDK 21.0.2，G1，服务器 8–20 GiB 堆、4 个逻辑处理器提示；每个隐藏客户端 8 GiB 上限、1 个处理器提示、10 FPS。
- 自然刷怪开启。固定机器负载保留：128 熔炉、128 漏斗和箱子、256 个 Create 传动杆。
- 三波普通生物和两波 Boss；客户端实际攻击、放置和破坏方块；每人 1,024 格分散探图（最终脚本 Y=336，避免固定路线撞山；原生碰撞检查保留），之后跨维度、重连、保存并重启。
- 增强轮次通过 NeoForge 标准生成事件刷入生物，补充死亡的 AI 战斗目标，并测试生存模式受伤、死亡、原生重生。死亡阶段明确开启保留物品，不覆盖墓碑找回流程。
- Neruina 拦截的实体 tick 异常也视为失败，不能用“服务器没退出”代替稳定性验证。

这些测试覆盖具体模组实体和操作组合，不是所有模组、所有 Boss 技能、长期内存泄漏或高人数容量的完整证明。

## 首轮探针

`build/thread-load-20260929-155820-043743` 未通过建造覆盖断言，不能算端到端通过。

两维度共刷入 264 个实体、22 种类型，记录 1,484 次伤害、157 次死亡。自动化角色持剑攻击后没有切回建造槽，创造模式持剑不能破坏方块，因此循环只完成少量放置。已修正为放置和破坏前都切换至建造槽。该失败是测试驱动问题，没有发现新的生物 tick 崩溃。

同时改进测试判定和可复现性：经验以战斗后快照为准；离线客户端 UUID 使用服务器的 OfflinePlayer 算法；保存各轮测试源码；保存并重启校验 8 个原版 / 模组实体的类型、UUID、生命状态、标签和 NoAI 状态。

## 第二轮探针

`build/thread-load-20260929-161155-675268` 的生物和建造覆盖检查通过：264 个实体、22 种类型，1,626 次伤害、144 次死亡，642 次放置、643 次破坏。战斗阶段平均约 16.76 TPS，平均 tick 工作 39.05 ms、P99 186.87 ms；四客户端和服务器共享同一机器，不能据此推算独立专用服务器容量。

这一轮在 Y=200 的固定探图路线未完成，不能算完整端到端通过，也不能用其长时间停留后的 TPS 作为有效探图基准。两名玩家到达 X=1024.5；另两名停在 X=507.7 和 X=1.3。保存的区块证实前方分别是 Y=201 的石山和 Y=200 的测试圆石墙。线程快照显示正常 tick 等待、加载队列空闲，没有 Java 死锁。最终自动路线改到世界最高建造高度以上，不关闭碰撞。

该轮战斗 JFR 的维度 tick 线程热点以方块状态读取、寻路路径类型判断为主；这是高密度生物 AI 压力，不应与之前单纯探图测试的 20 TPS 结论混同。JFR 计数是采样数，不是精确 CPU 时间占比。详见对应目录的 `combat-hotspots.txt`、`travel-thread-dump.txt` 和 `probe-summary.json`。

## 第三轮与提前中止的第四轮

`build/thread-load-20260929-163135-790546` 使用种子 67890，已通过生物、建造、生存受伤/死亡/重生和四人 1,024 格路线，进入跨维度收尾。四个客户端的当前区块缺失计数均为 0；战斗截图保留在各客户端目录。

该轮仍未完成端到端：一名玩家因战斗拾取额外钻石，存档中槽位 0 为 24 颗，而旧断言固定要求 23 颗。最终脚本先确认初始 23 颗没有减少，再保存战斗后测试钻石数量和经验快照，要求跨维度和重连后精确匹配。

进一步检查原生死亡后的玩家 NBT，发现测试自身放在临时实体数据里的初始化标记未保留，可能让后续重连重复授予初始物品和经验。`build/thread-load-20260929-165024-298725` 在加载阶段提前中止，未作为通过轮次。最终脚本在重生时恢复测试标记，并以服务端会话内 UUID 集合防止重复初始化。

第三轮停止后还观察到 Supplementaries 路牌定位线程延迟退出。JFR 的 `jdk.ThreadStart` 将线程定位到 `BlockGeneratorBlockTile.tick`，本地字节码显示其静态执行器为 `Executors.newCachedThreadPool()`。这类普通缓存线程在空闲期仍会存活约 60 秒，可能延迟退出；并非维度 tick 死锁。证据为该轮 `closing-thread-origin.txt` 和 `build/supplementaries-block-generator-bytecode.txt`。本任务未修改这个第三方线程池。

## 第五轮与机器负载隔离

`build/thread-load-20260929-165405-010675` 完成四人的生存受伤/死亡/重生、1,024 格路线、跨维度与重连。四个客户端均通过传送和重连后的测试钻石、经验、目标维度校验，当前区块缺失计数均为 0。战斗阶段为 1,708 次实体伤害、542 次放置、548 次破坏，平均约 19.05 TPS。

此轮最终在机器检查失败，仍不算完整通过。存档显示生存世界 X=15、Y=185、Z=0 的一台电机缺失；对应 16 根传动杆全部为零转速，其余电机、家园传动杆和两世界全部熔炉、箱子正常。证据为该轮 `saved-kinetics.json`。没有记录到具体破坏者，不能仅凭此断言是并发错误。

原测试战斗场搭在机器上方，场景中的破坏行为可能干扰固定负载。最终布局将战斗场移到 X=96，保留原生破坏行为和全部机器完整性断言，不通过关闭 Boss 破坏或忽略停转来取得通过结果。
